## 判断标准

S25 提示可见的 SIP 5xx 响应，表示某个 SIP 服务器或代理无法处理请求，需按 Call-ID 与 CSeq 追溯请求、重试和经由链。486 Busy Here 是终端忙线，属于不同类别；单个 5xx 也不能直接判定媒体路径故障。

## 排查步骤

在话机、SBC 和注册/代理服务器端对齐 INVITE、REGISTER、响应码和时间。区分请求未到达、响应未回客户端、代理主动给出 503 以及上游返回 5xx。若呼叫已建立但无声，继续检查 SDP 协商地址、媒体端口、RTP/RTCP 方向与 NAT/防火墙；信令成功不代表媒体成功。

SIP over TLS 未解密时通常只能看到 TLS 会话和传输中断，不能从抓包直接获得 SIP 状态码。结合 SBC 呼叫跟踪及服务日志复核；注意用户主动取消呼叫、忙线、拒接与服务器故障的区别。

来源：[RFC 3261：SIP](https://www.rfc-editor.org/info/rfc3261/)。

## 正常反例

终端忙线（486）、用户拒绝（603）和用户取消是业务结果，不等同于 SIP 服务器 5xx 故障。代理重试可能导致同一失败响应重复出现，统计受影响呼叫时应按 Call-ID 去重，而不能把每个响应都视为不同用户故障。
